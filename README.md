***REMOVED*** Бюджеты ЦФО — дашборд исполнения бюджетов

Веб-приложение для контроля исполнения годовых бюджетов центров финансовой
ответственности (дирекций): сколько выделено, сколько израсходовано, сколько
уже заявлено к оплате и сколько лимита осталось свободным.

Заменяет ручную работу в Excel: план приходит из файлов дирекций, факт — из
выгрузки 1С, обязательства заводятся в интерфейсе, а расчёт остатков,
контроль лимитов и журнал изменений ведёт система.

> Репозиторий содержит только код. Рабочие данные (суммы бюджетов, контрагенты,
> договоры) в него не попадают — см. `.gitignore`. Данные в макете обезличены.

***REMOVED******REMOVED*** Возможности

| Раздел | Что делает |
|---|---|

| **Бюджет** | планирование бюджета следующего года: все ЦФО одной таблицей, правка прямо в ячейках |
| **Сводка** | таблица по всем ЦФО: план / факт / заявки / остаток, фильтр по риску |
| **Карточка ЦФО** | строки бюджета по месяцам, привязанные платежи, добавление и удаление строк |
| **Заявки** | обязательства с проверкой свободного лимита (предупреждает, но не блокирует) |
| **Сопоставление** | привязка неразобранных платежей 1С к строкам бюджета, автосопоставление |
| **Тепловая карта** | отклонение факта от плана по месяцам, только закрытые периоды |
| **Корректировки** | перенос лимита между месяцами строки и между строками ЦФО + журнал |
| **Импорт / экспорт** | загрузка Excel с сопоставлением колонок, выгрузка в формат «Оперплан ЦФО» |
| **Справочник ЦФО** | поиск дублей названий, сведение с переносом данных, алиасы написаний |
| **Доступ** | учётные записи, пароли и привязка руководителей к ЦФО (только финотделу) |

Таблицы «Бюджета» и «Карточки ЦФО» фильтруются по ЦФО, статье, контрагенту,
договору и детализации: выбор из списка с поиском, несколько значений сразу.
Строка ИТОГО под шапкой считается по видимым строкам и меняется вместе с фильтрами.

***REMOVED******REMOVED*** Как считается

Формулы повторяют лист «Оперплан ЦФО» рабочего файла ликвидности:

```
Итого опер план  = Факт + неоплаченные заявки
Остаток бюджета  = БЮДЖЕТ − Факт                 (остаток по кассе)
Свободный лимит  = БЮДЖЕТ − Итого опер план      (колонка «Бюджет - опер план»)
```

Дополнительно:

- **Все суммы с НДС**, в рублях. В интерфейсе округляются до рублей, в Excel выгружаются с копейками.
- **Неиспользованный остаток месяца** переносится на следующий месяц внутри той же
  строки бюджета (флаг `carryover`); в конце года остаток обнуляется.
- **Отчётная дата** и «факт закрыт по месяц» задаются в шапке: от них считается
  ожидаемый темп освоения, с которым сравнивается фактический.
- **Статусы**: `перерасход` (факт > бюджета) → `заявки сверх лимита` (свободный лимит < 0)
  → `опережает темп` (освоение выше ожидаемого на 15 п.п.) → `в графике`.

***REMOVED******REMOVED*** Бюджет — планирование следующего года

Вкладка отвечает на вопрос «каким будет бюджет в следующем году» и живёт в
**отдельном слое данных**: дашборд, сводка, карточка ЦФО и привязанный факт из 1С
её не видят и от неё не меняются. Технически это колонка `budget.layer`:
`main` — исполнение текущего года, `operplan` — планирование.

Базу берут из листа **«Бюджеты ЦФО»** файла ликвидности:
`Статья оборотов | ЦФО | Контрагент | Договор | Детализация | Комментарий | ИТОГО | Январь…Декабрь`.
Блок открывается строкой ИТОГО — в ней и ЦФО-держатель бюджета, и контрольная сумма.
Держателем считается ЦФО блока, а не колонка ЦФО в самой строке: внутри блоков
встречаются строки с другой подписью, и контрольная сумма блока их включает.
Отличающаяся подпись сохраняется в «Комм наш».

Три показателя вкладки:

```
Бюджет нового года     сумма плана, который набирается
Бюджет базового года   + батарейка: какую долю нового бюджета он составляет
План-факт базового     + батарейка освоения; пока факт в слой не загружен — показывает ноль
```

Колонка **«Детализация»** заполняется по-разному: у дирекции ИТ туда идёт
столбец «Детализация» листа, у остальных — столбец «Комментарий». Управляет этим
поле `cfo.detail_source`; у ИТ оно выставляется при импорте. Если у строки ИТ
детализация пустая, показывается комментарий — иначе колонка была бы пустой.

**Повторить бюджет прошлого года** переносит строки вместе с помесячной разбивкой
и необязательной индексацией в процентах. Дубли пропускаются по ключу
`статья + контрагент + договор + детализация`, причём по кратности: если в базовом
году три одинаковых по ключу строки, переедут все три, а повторный запуск не
задвоит ничего.

**Внесение изменений заблокировано** — переключатель финансового отдела на год.
При замке руководители ЦФО план не правят, финансовый отдел правит.

Внизу страницы — **строки, которые были в базовом году и не попали в план**
(ключ `статья + контрагент + договор`), с кнопкой «Добавить в план» у каждой и
«Добавить все». Так теряется меньше расходов при пересборке года.

***REMOVED******REMOVED******REMOVED*** Правка таблицы

Карандаш «Редактировать» включает правку прямо в ячейках: клик по ячейке,

***REMOVED******REMOVED******REMOVED*** Загрузка исходных листов

На вкладке «Импорт / экспорт» добавлены два типа файла:

- **Бюджеты ЦФО (вкладка «Бюджет»)** — лист в слой планирования за указанный год.

***REMOVED******REMOVED*** Справочник ЦФО

В выгрузках название дирекции пишут по-разному, из-за чего один ЦФО распадается
на несколько. Вкладка «Справочник ЦФО» это лечит:

- **поиск дублей** — по вхождению, префиксу, расстоянию Левенштейна и совпадению
  значимых слов; основным предлагается тот ЦФО, где больше данных;
- **сведение** — бюджеты, строки, факт, заявки и корректировки переезжают на
  оставляемый ЦФО, одноимённые бюджеты объединяются со сквозной перенумерацией строк;
- **алиасы** — прежнее написание запоминается, следующий импорт дубль не создаст;
- **переименование** с сохранением старого названия как алиаса и удаление пустых записей.

Перед сведением показывается, что именно произойдёт (суммы после, какие бюджеты
объединятся). Действие необратимо и пишется в журнал изменений. Названия,
отличающиеся только пробелами или регистром, сводятся автоматически при импорте.

***REMOVED******REMOVED*** Роли и доступ

- **Финансовый отдел** — все вкладки и все ЦФО: настройки периода, сопоставление платежей, загрузка файлов, справочник.
- **Руководитель ЦФО** — две вкладки, **«Бюджет»** и **«Карточка ЦФО»**, и только свои ЦФО.
  Остальные вкладки скрыты, а закрытые ему данные не отдаёт и сервер: дашборд, сводка,
  тепловая карта, заявки и журнал фильтруются по списку ЦФО либо возвращают 403.
  Галочка «показать все статьи и контрагентов» — только у финотдела: справочник
  выпадающих списков тоже обрезан по доступным ЦФО, чужие контрагенты и номера
  договоров на клиент не уезжают.

Ограничение считается по `cfo_ids` учётной записи (`app/auth.py`), проверяется в каждом
роутере и не зависит от того, что показал интерфейс.

***REMOVED******REMOVED******REMOVED*** Вход по логину и паролю

Пока финотдел не задал первый пароль, приложение работает как раньше — в **режиме
доверенной сети**: экран входа не показывается, роль выбирается переключателем в шапке,
защита только от случайной правки чужого ЦФО. В шапке при этом висит кнопка
**«Настроить вход»**: она задаёт пароль учётной записи `fin` — и этим закрывает
приложение. После настройки любой запрос без сессии получает 401, и экран входа
поднимается сам.

Дальше учётные записи заводятся на вкладке **«Доступ»** (видна только финотделу):
логин, имя для журнала, роль, список доступных ЦФО и пароль. Там же пароль сбрасывается,
учётка отключается и удаляется. Свой пароль каждый меняет кнопкой «Пароль» в шапке.

- Пароли хранятся только как PBKDF2-HMAC-SHA256 (240 000 итераций, соль на пароль).
- Сессия живёт 12 часов в cookie `budget_session` (`httponly`, `samesite=lax`) и
  продлевается, когда прошла половина срока.
- Смена пароля, смена роли или списка ЦФО, отключение и удаление **закрывают сессии**
  учётной записи — права обновятся при следующем входе, а не когда-нибудь.
- Последнюю рабочую учётку финотдела нельзя понизить, отключить или удалить, и нельзя
  удалить ту, под которой вошли, — иначе управлять доступом станет некому.
- Переключатель роли остаётся только у финотдела: руководителю он не нужен и на сервере
  запрещён — заголовок `X-User: cfo:<id>` от руководителя игнорируется.

***REMOVED******REMOVED*** Развёртывание

Деплой по SSH одной командой. Секреты в скрипте не хранятся: доступ берётся из
переменных окружения либо из внешнего xlsx с параметрами сервера.

```bash
set DEPLOY_CREDS=<путь к файлу с данными сервера.xlsx>
***REMOVED***   или: set DEPLOY_USER=... & set DEPLOY_PASS=... & set DEPLOY_HOST=...

python scripts/deploy.py check      ***REMOVED*** окружение сервера: python, порт, служба
python scripts/deploy.py deploy     ***REMOVED*** выложить код, поставить зависимости, запустить
python scripts/deploy.py restart    ***REMOVED*** перезапустить
python scripts/deploy.py logs       ***REMOVED*** последние строки журнала
python scripts/deploy.py stop       ***REMOVED*** остановить
```

Скрипт выкладывает код в `$HOME/cfo-budget-dashboard`, создаёт venv, ставит
зависимости и регистрирует службу **пользовательского** systemd
(`systemctl --user`) — root для этого не нужен, приложение поднимается после
перезагрузки сервера благодаря `loginctl enable-linger`. Если linger включить
не удалось, скрипт откатывается на запуск через `nohup` и об этом сообщает.

База (`data/budget.db`) при обновлении кода не затирается: архив содержит только
код, каталог `data/` в него не попадает.

Если администратор захочет системную службу в `/opt/apps` (как у fin-dashboard),
готовый unit-файл — `deploy/cfo-budget.service`.
