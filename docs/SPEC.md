***REMOVED*** Спецификация: дашборд бюджетов ЦФО

Документ фиксирует требования, принятые решения и модель данных. Составлен по
итогам разбора рабочих файлов бюджетирования и согласования требований.

***REMOVED******REMOVED*** 1. Задача

Годовой бюджет выделяется на ЦФО (дирекции) и отслеживается по месяцам
накопительно. Сейчас контроль ведётся в Excel: план собирается из файлов
дирекций, факт сверяется вручную, обязательства держатся в голове и в столбцах
рабочего файла. Нужен инструмент, который отвечает на два вопроса:

1. **Сколько осталось от лимита** — по ЦФО, бюджету и строке.
2. **Где перерасход** — и по факту, и с учётом уже поданных заявок.

***REMOVED******REMOVED*** 2. Единицы и соглашения

- Валюта — рубли, все суммы **с НДС**.
- Интерфейс округляет до рублей, Excel-выгрузка отдаёт точные суммы с копейками.
- Год — единица планирования; поддерживается архив прошлых лет (переключатель года).
- ЮЛ в бюджетном контроле не участвует.
- ФОТ и налоги в дашборд не входят — они ведутся отдельно.

***REMOVED******REMOVED*** 3. Структура бюджета

```
ЦФО (дирекция)
└── Бюджет            «Бюджет обязательных затрат», «Бюджет развития», «Основной бюджет»
    └── Строка        статья оборотов + контрагент + договор + детализация
        ├── план по месяцам (12)
        ├── факт        — платежи, привязанные к строке
        └── заявки      — неоплаченные обязательства
```

Одна строка — уникальная комбинация статьи, контрагента, договора и детализации.
Лимит контролируется на трёх уровнях: строка → бюджет → ЦФО.

***REMOVED******REMOVED*** 4. Формулы

```
Итого опер план  = Факт + неоплаченные заявки
Остаток бюджета  = БЮДЖЕТ − Факт
Свободный лимит  = БЮДЖЕТ − Итого опер план
Освоение, %      = Факт / БЮДЖЕТ
```

Выверено на рабочем файле: колонка «Бюджет - опер план» = `БЮДЖЕТ − Итого опер план`,
колонка «Остаток бюжета» = `БЮДЖЕТ − Факт`. Колонка «Оперплан фикс» дублирует
оперплан на отчётную дату и в системе не воспроизводится.

***REMOVED******REMOVED******REMOVED*** Перенос остатка

Неиспользованный остаток месяца увеличивает лимит следующего месяца **внутри той
же строки**:

```
limit[m] = plan[m] + carry[m-1]
carry[m] = max(0, limit[m] − факт[m] − заявки[m])
over[m]  = max(0, факт[m] + заявки[m] − limit[m])
```

В конце года перенос обнуляется. Поведение управляется флагом `carryover` строки.

***REMOVED******REMOVED******REMOVED*** Отчётная дата и ожидаемый темп

Финансовый отдел задаёт «факт закрыт по месяц» и отчётную дату. Ожидаемый темп
освоения = `(закрытые месяцы + пройденная часть текущего) / 12`. С ним
сравнивается фактическое освоение — отсюда статус.

***REMOVED******REMOVED******REMOVED*** Статусы

| Статус | Условие |
|---|---|
| `перерасход` | Факт > БЮДЖЕТ |
| `заявки сверх лимита` | Свободный лимит < 0 |
| `опережает темп` | Освоение > ожидаемого темпа + 15 п.п. |
| `в графике` | остальные |

***REMOVED******REMOVED******REMOVED*** Особенности разбора

Проверено на рабочих файлах, парсер это учитывает:

- **Шапка не в первой строке** (в оперплане — 5-я, в файлах дирекций — 3-я).
- **Колонка с номерами строк без заголовка** — определяется по содержимому слева от статьи.
- **«БЮДЖЕТ» и «Бюджет - опер план»** — точное совпадение названия колонки
  приоритетнее частичного, иначе лимит берётся из неверной колонки.
- **Метки ФАКТ / ПРОГНОЗ** над шапкой задают границу закрытого периода.
- **Блок открывается строкой «ИТОГО»**, где указаны ЦФО и название бюджета;
  итоговые строки в суммы не попадают, но их значения используются для сверки.
- **Строки без номера с пометкой «Из строки N бюджет»** — платежи, привязанные к лимиту строки N.
- **Персональные колонки с ФИО** в заголовке распознаются как комментарий согласующего.
- **Названия ЦФО не нормализованы** в источнике (встречаются варианты написания) —
  предусмотрена таблица алиасов.

***REMOVED******REMOVED*** 6. Правила работы

- **Лимиты жёсткие по смыслу, но система предупреждает и пропускает**: заявка или
  платёж сверх свободного лимита сохраняется с пометкой «сверх лимита».
- **«Вне бюджета»** — ручной признак расхода. Такие суммы не уменьшают лимит, а
  показываются отдельным блоком в сводке и выгружаются реестром.
- **Ручные правки устойчивы к перезагрузке файлов**: повторная загрузка факта
  отсекает дубли по ключу (номер заявки, дата, сумма, контрагент, договор).
- **Корректировки лимита** разрешены только между месяцами внутри строки и между
  строками внутри одного ЦФО. Обоснование обязательно, всё пишется в журнал.
- **Сопоставление факта** — по договору (4 балла), статье (3), контрагенту (2), ЦФО (1);
  автоматически привязываются платежи с номером заявки или суммой баллов ≥ 7.

***REMOVED******REMOVED*** 7. Роли

| Роль | Права |
|---|---|
| Финансовый отдел | все ЦФО, настройки периода, сопоставление платежей, импорт и экспорт |
| Руководитель ЦФО | только свои ЦФО: строки, заявки, признак «вне бюджета», комментарии |

Способ аутентификации определяет ИТ-отдел (планируется домен AD). До этого
пользователь берётся из заголовка `X-User`; пароли не хранятся и не проверяются.
Точка замены — `current_user` в `app/auth.py`.

***REMOVED******REMOVED*** 9. Технические решения

- **Стек**: FastAPI + SQLite (raw SQL, без ORM) + Vanilla JS без сборки.
- **Порт** 8000 на том же сервере, где работают остальные дашборды.
- **Дизайн** взят с дашборда рассадки: тёмная тема, фиолетовый акцент, Calibri.
- **Данные компании не попадают в репозиторий**: база, выгрузки и данные макета
  исключены через `.gitignore`.

***REMOVED******REMOVED*** 10. Отложено

- Согласование заявок (workflow «черновик → на согласовании → утверждена»);
  сейчас заявка — просто запланированная сумма.
- Автоматическая выгрузка из 1С. Ближайший вариант — регламентное задание 1С
  кладёт файл в сетевую папку, приложение забирает его по расписанию;
  дальше — HTTP-сервис 1С. Слой импорта к этому готов: источник подменяется
  без изменения логики.
- Уведомления по почте — пока достаточно подсветки в интерфейсе.
- Сравнение год к году.
- Доменная аутентификация.
